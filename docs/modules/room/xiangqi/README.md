# 象棋房间模块

更新时间：2026-05-23

象棋房间模块是通用房间模块委派的具体游戏房间模块，负责象棋地图、两方座位、棋盘布局、权威局面、走法校验、回合推进、胜负与和棋判定、事件下发和复盘。它回答“当前这局象棋如何显示、谁该走、一步棋是否合法、局面如何变化、什么时候结束”。

房间模块提供房间上下文、参与者、座位、玩家通道、网络同步、可见历史、重连和主机接管。象棋房间模块只生产象棋公开状态、行动请求、事件 payload、特效请求和恢复材料；它不关心玩家响应来自真人还是 AI。

玩家响应由 [象棋真人玩家模块](../../player/xiangqi/human/README.md) 和 [象棋 AI 玩家模块](../../player/xiangqi/ai/README.md) 通过通用玩家模块收集。主机程序持有唯一权威局面，负责规则推进和胜负判定。

跨模块对象 `GameRoomMap`、`GameRoomSceneSlots`、`XiangqiActionRequest`、`XiangqiPlayerActionResult`、`XiangqiRuleUpdateResult` 的字段权威见 [跨模块契约](../../../contracts/README.md)。

## 模块定位

```text
房间模块
  -> 象棋房间模块
       -> 提供象棋地图列表
       -> 提供 2 人座位和观察者布局
       -> 初始化棋盘和行棋方
       -> 生成走棋、认输、求和、悔棋等请求
       -> 接收玩家行动结果
       -> 校验走法和回合
       -> 推进局面、记录棋谱和聊天
       -> 判定将军、将死、困毙、认输、和棋和超时
       -> 输出公开事件、临时数据、复盘和恢复材料
  -> 房间模块包装成快照并同步
```

象棋是完全公开信息游戏，默认不需要狼人杀那类按身份脱敏的私有规则状态。但玩家通道、控制权、重连 token、设备身份、模型配置、API Key 和本机偏好仍然不能下发给非授权参与者。

## 本阶段补充约束

你提出的方向可行，还需要补齐这些设计点：

- 棋盘规则：必须固定采用中国象棋规则，包括九宫、河界、蹩马腿、塞象眼、炮隔子、将帅照面、不能送将、将军、将死和困毙。
- 局面表示：权威状态需要保存棋子、行棋方、回合数、半回合数、最后一步、被将军方、可用操作和结果状态。
- 行动类型：第一版直接支持认输、求和、同意求和、拒绝求和、申请悔棋、同意悔棋、拒绝悔棋、计时开启时的棋钟超时和断线暂停。
- AI 行棋与 AI 聊天分离：AI 需要按回合自动走棋，但不主动聊天；只有真人玩家发言后，AI 才根据该发言生成回应。
- 聊天不推进棋局：玩家发言只进入聊天记录和 TTS，不改变行棋方，也不触发走棋校验。
- 棋盘视角：横屏应用中间放竖版棋盘；红方和黑方玩家显示在左右两侧。每个玩家看到同一权威棋盘，但可按本机视角旋转或不旋转，不能改变权威坐标。
- 触控输入：真人走棋用“选中己方棋子 -> 选择目标格”或拖拽；提交前可取消选择，提交后由主机校验。
- 重连恢复：断线后恢复当前棋盘、行棋方、棋谱、聊天记录、未处理的求和/悔棋请求和计时开启时的计时器。
- 复盘：结束后公开完整棋谱、聊天记录和结束原因；不公开模型 prompt、API Key 或 AI 草稿。
- 计时策略：第一版支持简单棋钟，但创建房间默认不计时。创建房间提供计时开关；开启计时后显示时间下拉，默认 10 分钟。未开启计时时不扣时、不触发超时判负；开启后主机按房间权威时间给当前需响应玩家扣时，断线、暂停、求和/悔棋等待对手确认时停止扣时。

## UI 布局

横屏房间内采用三列布局：

```text
左侧玩家区                 中间棋盘区                   右侧玩家区
红方或本机玩家卡片          竖版象棋棋盘                 黑方或对手玩家卡片
发言记录                    棋局状态 / 最近一步          发言记录
操作按钮                    聊天输入 / 跳过播报          操作按钮
```

布局约定：

- 中间棋盘保持中国象棋竖版比例，优先占据屏幕高度。
- 左右玩家区固定显示座位、头像、昵称、在线状态、剩余时间、当前是否轮到该方和最近发言。
- 每侧有对应发言记录；全局聊天仍按房间事件保存，UI 可以按发言方归入左右侧。
- 玩家发言和 AI 回应显示在对应侧发言区，棋局系统消息显示在棋盘区或历史区，不放到系统警告 toast。
- 系统警告 toast 只显示断线、重连、非法操作、安装/权限类提示。
- 走棋特效只来自象棋房间模块接受后的结果，例如移动、吃子、将军、胜负和求和状态变化。

## 玩家和座位

象棋固定 2 个玩家座位：

| 座位 | 阵营 | 默认显示 |
| --- | --- | --- |
| 1 | 红方 | 左侧或本机侧 |
| 2 | 黑方 | 右侧或对手侧 |

约定：

- 红方默认先行。
- 房间模块维护座位占用、玩家资料、观察者和在线状态。
- 象棋房间模块只保存红黑方绑定、当前行棋方和棋局状态。
- 观察者可以看公开棋盘、棋谱和聊天，但不能提交走棋、求和、悔棋或认输。
- 本机点击离座只从棋手位切换到观战位，不等同于退出房间；只有点击退出才清理本机观战身份并按“是否还有真人参与者”决定是否销毁房间。
- 换座、加入机器人、退出和重连仍走通用房间模块。

## 权威状态

象棋房间模块维护的权威状态至少包括：

| 字段 | 说明 |
| --- | --- |
| `board` | 10 x 9 棋盘，保存棋子类型、颜色和位置。 |
| `side_to_move` | 当前行棋方，`red` 或 `black`。 |
| `turn_number` | 完整回合数。 |
| `ply_number` | 半回合数。 |
| `move_history` | 已接受走棋列表。 |
| `captured_pieces` | 被吃棋子列表。 |
| `last_move` | 最近一步。 |
| `check_side` | 当前被将军方，可空。 |
| `pending_draw_offer` | 待处理求和请求，可空。 |
| `pending_undo_offer` | 待处理悔棋请求，可空。 |
| `clock_state` | 计时状态；仅在创建房间开启计时时维护和使用，可空。 |
| `game_result` | 未结束、红胜、黑胜、和棋、异常中止。 |
| `result_reason` | 将死、困毙、认输、和棋、超时、断线中止等。 |

坐标约定：

- 权威坐标使用红方视角：`file = 0..8` 从红方左到右，`rank = 0..9` 从红方底线到黑方底线。
- UI 可以根据本机视角旋转展示，但提交给象棋房间模块的坐标必须转换回权威坐标。
- 棋谱可以同时保存结构化坐标和展示文本，展示文本不作为规则校验来源。

## 棋钟

第一版支持可选简单总时长棋钟。创建房间默认不计时；开启计时后显示时间下拉，默认 10 分钟。

| 字段 | 说明 |
| --- | --- |
| `clock_enabled` | 是否开启计时，默认 `false`。 |
| `time_limit_ms` | 每方初始总时长；开启计时后默认 600000。 |
| `red_remaining_ms` | 红方剩余时长。 |
| `black_remaining_ms` | 黑方剩余时长。 |
| `running_side` | 当前正在扣时的一方，可空。 |
| `started_at_ms` | 当前扣时段开始时间，使用主机权威时间。 |
| `paused` | 是否暂停扣时。 |
| `pause_reason` | `room_paused`、`disconnected`、`draw_pending`、`undo_pending`、`presentation_wait` 等。 |

计时规则：

- `clock_enabled = false` 时不维护剩余时间、不生成 `timeout` 行动、不因用时判负。
- `clock_enabled = true` 时才维护 `clock_state`，并按 `time_limit_ms` 初始化红黑双方剩余时间。
- 正常走棋时只扣当前行棋方时间。
- 求和或悔棋请求发出后，停止原行棋方扣时，等待对手同意或拒绝。
- 对手处理求和或悔棋响应时，第一版不扣对手棋钟，避免把社交确认计入行棋时间。
- 玩家断线、房间暂停、主机接管和展示 ACK 等待期间停止扣时。
- 走棋被象棋房间模块接受后，结算本步用时，再切换到对手扣时。
- 非法走棋不切换行棋方，继续扣当前行棋方时间。
- 任一方剩余时长小于等于 0 时，由主机生成 `timeout` 行动并提交象棋房间模块判负。
- 第一版不做读秒、加秒和多阶段用时；这些作为后续地图变体。

## 行动编排

正常走棋流程：

```text
象棋房间模块生成 XiangqiActionRequest(move)
  -> 具体游戏真人/AI 玩家模块
  -> 玩家模块投递或 AI 自动生成结果
  -> XiangqiPlayerActionResult
  -> 象棋房间模块校验
  -> XiangqiRuleUpdateResult(ok = true)
  -> 房间模块广播棋盘、棋谱、特效和下一步请求
```

行动类型：

| `action_type` | 说明 |
| --- | --- |
| `move` | 走棋。 |
| `resign` | 认输。 |
| `draw_offer` | 提出求和。 |
| `draw_accept` | 同意求和。 |
| `draw_decline` | 拒绝求和。 |
| `undo_offer` | 申请悔棋。 |
| `undo_accept` | 同意悔棋。 |
| `undo_decline` | 拒绝悔棋。 |
| `timeout` | 超时结果，仅计时开启时由主机计时产生。 |
| `chat` | 已确认发言事件，不改变棋局。 |

约定：

- 只有当前行棋方可以提交 `move`。
- `resign` 可以由任一未结束玩家提交。
- 求和和悔棋需要对手响应；计时开启时，等待响应期间暂停棋钟。
- 悔棋第一版启用，只允许退回最近一手完整走棋；对手必须显式同意或拒绝。
- AI 收到求和或悔棋请求时也必须返回同意或拒绝，不允许静默跳过。
- `chat` 只用于记录和触发 AI 聊天回应，不进入走棋合法性校验。

## 规则校验

象棋房间模块必须完成最终校验：

- 行动者是否是该座位绑定玩家。
- 棋局是否未结束。
- 是否轮到该方走棋。
- 起点是否有己方棋子。
- 终点是否在棋盘内。
- 终点是否没有己方棋子。
- 棋子走法是否合法。
- 马腿、象眼、炮隔子、士象活动范围、将帅九宫和兵卒过河规则是否满足。
- 走子后己方将帅不能被将军。
- 将帅不能照面。
- 是否形成将军、将死或困毙。
- 求和、悔棋、认输和超时是否符合当前状态。

悔棋规则：

- 只有棋局未结束时可以申请悔棋。
- 任一玩家都可以申请悔棋。
- 同一时间只能存在一个待处理悔棋请求。
- 第一版只允许撤销最近一手已接受 `move`。
- 悔棋被同意后恢复到上一局面，恢复被吃棋子、行棋方、将军状态和棋钟状态，并写入公开历史。
- 悔棋被拒绝后不改变棋盘和行棋方；计时开启时继续原行棋方计时。
- 悔棋请求、同意和拒绝都进入公开历史。

求和规则：

- 只有棋局未结束时可以申请求和。
- 同一时间只能存在一个待处理求和请求。
- 求和被同意后立即结束为和棋。
- 求和被拒绝后不改变棋盘和行棋方；计时开启时继续原行棋方计时。
- 求和请求、同意和拒绝都进入公开历史。

认输规则：

- 任一未结束玩家可以认输。
- 认输立即结束，对手获胜。
- 真人认输必须二次确认。

真人 UI 和 AI 可以预估合法走法用于交互和提示，但最终结果必须由象棋房间模块校验。非法行动只返回错误和提示，不写入棋谱、历史、TTS 或 AI 记忆。

## AI 行为

AI 玩家分两种行为：行棋和聊天。

行棋：

- AI 到自己回合时必须自动响应 `XiangqiActionRequest(move)`。
- AI 行棋输入只包含公开棋盘、棋谱、当前行棋方、可选合法走法和规则摘要。
- AI 输出结构化走法，不能直接修改棋盘。
- 第一版 AI 可先用本地合法走法选择器生成结构化结果；后续接模型时仍必须返回同一行动结构。
- 主机不调用模型，控制 AI 的设备本机读取机器人档案和模型配置后生成结果。
- 模型输出解析失败或非法走法时返回结构化错误，默认不推进棋局。
- AI 收到求和或悔棋响应请求时，必须结构化返回同意或拒绝。

聊天：

- AI 不主动发言。
- 真人玩家公开发言被房间接受后，才可以触发对侧 AI 的聊天回应请求。
- AI 聊天回应必须以象棋对局语境生成，不承载走棋结果。
- AI 聊天回应进入对应玩家发言记录和 TTS，但不改变 `side_to_move`、棋盘或棋钟。
- 是否允许 AI 回应每一句话、是否限流、是否只回应直接提及，需要在房间规则配置中固定。

## 可见性和历史

象棋默认公开这些数据：

- 棋盘局面。
- 行棋方。
- 棋谱。
- 吃子记录。
- 将军、胜负、和棋、认输和超时事件。
- 玩家公开发言和 AI 回应。
- 求和和悔棋请求及处理结果。

不公开这些数据：

- 玩家通道内部 ID、重连 token、设备私钥和认证材料。
- AI 模型配置、API Key、prompt、模型草稿和解析中间态。
- 本机未提交的选中棋子、拖拽位置和聊天草稿。

## 地图和规则配置

第一版提供一个标准地图：

| `map_id` | 人数 | 规则 |
| --- | --- | --- |
| `xiangqi_standard` | 2 | 红先、标准中国象棋、无让子、公开聊天、启用求和、启用悔棋、启用认输、可选简单棋钟且默认关闭。 |

后续可以增加：

- 快棋：更短总时长。
- 让子局：开局移除指定棋子。
- AI 教学局：允许提示合法走法和局面建议。
- 复盘局：不允许走棋，只允许查看棋谱和聊天。

## 复盘和恢复

复盘数据：

- 初始局面。
- 完整结构化棋谱。
- 每步后的局面摘要。
- 吃子、将军和胜负事件。
- 公开聊天记录。
- 结束原因。

恢复数据：

- 当前权威棋盘。
- 当前行棋方和计时开启时的计时器。
- 棋谱和聊天记录。
- 待处理求和/悔棋请求。
- 当前玩家未完成的行动请求。

主机接管时，恢复数据必须由房间模块和象棋房间模块共同校验 `host_epoch`、`snapshot_version` 和最近接受事件，不能重放未接受的 UI 草稿或模型草稿。

## 维护规则

- 象棋规则、棋盘坐标、胜负和棋判定只写在象棋房间模块。
- 通用房间模块不写象棋棋子走法、将军或将死判断。
- 真人玩家模块只收集输入，不裁决棋局。
- AI 玩家模块只生成候选走法或聊天文本，不直接改棋盘。
- 聊天链路和走棋链路必须分离。
- 所有进入棋谱、历史、TTS 和复盘的数据必须先被象棋房间模块或房间模块接受。
- 新增规则变体先更新地图规则文档，再更新代码和测试。
