# 狼人杀事件与历史

更新时间：2026-05-16

狼人杀存在公开事实、玩家私有事实、狼队私有事实和复盘事实。房间模块只负责事件外壳、序号、下发范围、inbox、补发和下载；狼人杀房间模块必须给每条事件明确下发范围，并为不同接收者生成对应的下发记录。

## 历史分层

- 公开历史：主持人公告、公开发言、投票公布、死亡公告、胜负结果、赛后总结和 MVP 结果。
- 玩家私有事件：身份发放、预言家查验结果、女巫药水信息、守卫守护限制、猎人开枪资格。
- 狼队私有事件：狼队成员信息、狼人夜聊、狼队目标意图和狼队目标票。
- 复盘事件：游戏结束后由 `replay_round` 回合显式生成，可以包含完整身份、夜晚行动和关键路径。

夜晚行动记录是玩法事实，不等于公开历史。它可以进入私有事件、房间副本或复盘材料，但不能绕过地图规则包的下发策略直接广播给所有玩家。

狼人杀房间模块内部保存权威结构化数据。权威数据包含夜晚行动、行动来源、行动目标、结算原因、技能状态、阶段状态和胜负路径。权威数据只能给规则执行、主机接管和复盘生成使用，不能直接作为玩家下发队列。

玩家下发队列必须由地图规则包派生。同一条权威事实可以派生成公开记录、本人记录、狼队记录、房主运行记录或复盘记录；也可以在某些视角下完全不生成记录。

## 事件输出

狼人杀房间模块只生成事件业务内容和下发范围建议，房间模块负责包装 `RoomEventEnvelope`、分配 `sequence`、写入 inbox、补发和下载。

建议事件类型：

| `event_kind` | 下发范围 | 触发点 | payload 要点 |
| --- | --- | --- | --- |
| `werewolf.map_selected` | `public` | 创建或开局前 | 地图 ID、地图名、人数、场景。 |
| `werewolf.game_started` | `public` | 开局成功 | 天数、地图规则摘要、参与者座位。 |
| `werewolf.role_dealt` | `player_private` | 开局发身份 | 目标玩家身份、阵营、私有提示。 |
| `werewolf.wolf_team_revealed` | `player_private` | 开局发身份 | 狼队成员列表，只给狼人。 |
| `werewolf.phase_changed` | 按阶段决定 | 阶段推进 | 阶段、天数、下一步行动摘要。 |
| `werewolf.action_requested` | `player_private` | 需要玩家行动 | `turn_id`、行动类型、目标候选、当前玩家输入摘要。 |
| `werewolf.speech_accepted` | `public` 或 `player_private` | 发言被接受 | 发言者、文本、发言模式。 |
| `werewolf.night_action_recorded` | `host_only` 或 `player_private` | 夜晚行动被接受 | 行动者、行动类型、目标摘要。 |
| `werewolf.seer_result` | `player_private` | 预言家查验 | 目标与查验阵营，只给预言家。 |
| `werewolf.wolf_chat` | `player_private` | 狼人夜聊 | 发言者、文本、狼队目标意图。 |
| `werewolf.vote_cast` | `host_only` 或 `player_private` | 单个投票被接受 | 投票者、目标。 |
| `werewolf.vote_resolved` | `public` | 投票结算 | 票型、结果、出局玩家。 |
| `werewolf.death_announced` | `public` | 死亡公布 | 死亡玩家、公开原因文案。 |
| `werewolf.game_over` | `public` | 胜负产生 | 胜利方、结束原因。 |
| `werewolf.post_game_summary` | `public` | 赛后总结被接受 | 玩家、总结文本。 |
| `werewolf.mvp_result` | `public` | MVP 投票完成 | MVP 玩家、票型摘要。 |
| `werewolf.replay_round_started` | `replay_round` | 复盘回合开始 | 复盘回合数据引用。 |

事件规则：

- 私有事件必须带目标玩家或目标参与者。
- 公开事件不得包含未公开身份、夜晚私有目标、药水状态、守护目标或狼人夜聊。
- 特效请求可以随事件 payload 或 `WerewolfRuleUpdateResult.effect_requests` 返回，但必须来自已接受的规则结果。
- 同一个行动可以产生多条事件，例如女巫行动被接受后可能同时产生私有药水事件、夜晚记录事件和后续阶段事件。
- 复盘事件只能在胜负产生后由 `replay_round` 回合生成，不从临时历史直接外放。

## 下发记录生成

地图规则包决定一条权威事件如何下发。下发策略至少需要同时考虑：

| 维度 | 说明 |
| --- | --- |
| 地图与人数 | 不同地图、不同人数下的身份池、技能和夜晚结算不同。 |
| 当前阶段 | 夜晚、白天、投票、遗言、猎人开枪和赛后允许下发的信息不同。 |
| 事件类型 | 发言、投票、查验、守护、用药、击杀、死亡、胜负等事件有不同公开范围。 |
| 接收者身份 | 狼人、预言家、女巫、守卫、猎人、平民拿到的队列不同。 |
| 接收者座位 | 本人、队友、行动目标、死亡玩家和旁观者可能拿到不同文本。 |
| 复盘回合状态 | 游戏中队列和游戏结束后的复盘回合队列分开生成。 |

下发记录是程序生成的结构化数据，可以同时服务 UI 和 AI 机器人玩家：

- UI 可以根据结构化记录渲染头像、名字、身份标签、频道样式和特效。
- AI 机器人玩家只在需要回答时，把自己队列中的结构化记录压缩成 `records` 文本数组。
- 真人玩家断联恢复时，只恢复狼人杀房间模块已经为该玩家生成的下发队列。
- 玩家适配层不能重新推断某条权威事实应该展示给谁。

## 平安夜与死亡原因

平安夜、死亡公告和夜晚结算必须按地图规则包生成下发数据，不能把权威原因直接广播。

示例约束：

- 平安夜公开记录只表达地图规则允许的结果，例如“昨夜无人死亡”。它不暴露狼人是否刀中、女巫是否救人、守卫是否守中、女巫是否用药。
- 如果夜晚有人死亡，公开记录只表达地图规则允许公开的死亡文案，例如“昨夜 6 号死亡”。是否展示死因，由具体地图规则决定。
- 死亡玩家不天然知道自己是被狼人击杀、被女巫毒杀，还是被猎人开枪带走。只有地图规则明确要求下发时，才生成对应本人记录。
- 女巫用药状态只进入女巫本人队列、房主运行数据或复盘材料；公开队列不出现“女巫救人/毒人”这类事实。
- 狼人击杀目标和狼队夜聊只进入狼队队列、房主运行数据或复盘材料；公开队列不出现夜晚目标。
- 守卫守护目标和连续守护限制只进入守卫本人队列、房主运行数据或复盘材料。
- 猎人开枪是公开阶段行动时，公开记录可以出现开枪行为和目标；若某地图存在非公开触发，公开文案由该地图规则包决定。

## 下发范围规则

- 身份信息默认只对本人可见。
- 狼人之间可以看到同伴和狼人夜聊。
- 预言家只看到自己的查验结果。
- 女巫只看到药水和规则允许的夜晚信息。
- 守卫只看到自己的守护历史和约束。
- 猎人只看到自己是否可开枪。
- 公开历史只包含规则允许公开的事实和发言。
- 游戏结束后的复盘公开内容必须通过 `replay_round` 回合生成。

下发记录给 AI 玩家使用前，由狼人杀 AI 玩家模块映射成通用输入上下文；狼人杀房间模块只负责提供已经按接收者生成的狼人杀数据。
