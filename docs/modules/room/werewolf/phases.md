# 狼人杀阶段编排

更新时间：2026-05-20

狼人杀阶段状态机描述游戏执行，不描述房间生命周期。阶段推进只由狼人杀房间模块执行。房间模块可以同步阶段结果，但不解释阶段含义。

## 通用阶段状态机

```text
lobby
  -> sheriff_speech -> sheriff_vote -> wolf_action
  -> 或直接 wolf_action
  -> guard_action
  -> seer_action
  -> witch_action
  -> sheriff_badge_action（警长死亡时）
  -> sheriff_speech_order
  -> day_discussion
  -> vote
  -> sheriff_badge_action（警长放逐或被猎人带走时）/ hunter_action / last_words / next night / game_over
  -> replay_round
  -> post_game_summary
  -> mvp_vote
  -> completed
```

不同地图可以通过自己的阶段计划启用或跳过警长、守卫、女巫、猎人等阶段。

## 阶段细则

| 阶段 | 进入条件 | 行动请求 | 完成条件 | 下一步 |
| --- | --- | --- | --- | --- |
| `lobby` | 房间创建后，尚未开局。 | 无。 | 房间模块确认人数和 ready，调用 `start_game()`。 | 有警长流程进入 `sheriff_speech`，否则进入 `wolf_action`。 |
| `sheriff_speech` | 地图规则配置启用警长流程。 | 对候选玩家依次下发 `speak`。 | 候选发言完成。 | `sheriff_vote`。 |
| `sheriff_vote` | 警长发言完成。 | 对存活玩家依次下发 `sheriff_vote`。 | 所有有资格玩家投票完成。 | 产生警长，进入 `wolf_action`。 |
| `wolf_action` | 夜晚开始或警长产生后。 | 对狼人行动者下发 `wolf_kill`；狼队夜聊和目标票作为私有流程辅助。 | 狼人袭击目标被接受，或无存活狼人自动跳过。 | `guard_action` 或下一可用夜晚阶段。 |
| `guard_action` | 地图启用守卫且狼人行动之后。 | 对守卫下发 `guard_protect`。 | 守护目标被接受，或无守卫自动跳过。 | `seer_action`。 |
| `seer_action` | 守卫行动之后，或地图不启用守卫时狼人行动之后。 | 对预言家下发 `seer_check`。 | 查验目标被接受，或无预言家自动跳过。 | `witch_action` 或夜晚结算。 |
| `witch_action` | 地图启用女巫且预言家行动之后。 | 对女巫下发 `witch_act`。 | 救、毒或跳过被接受，或无可用药水自动跳过。 | 结算夜晚，进入白天入口；可能先处理 `sheriff_badge_action`、`hunter_action`、`last_words` 或 `game_over`。 |
| `sheriff_badge_action` | 地图启用警长，当前警长已经死亡，且本局尚未结束。 | 对死亡警长下发 `sheriff_badge_action`；飞警徽选择一名存活玩家，撕警徽不选择存活目标。 | 死亡警长选择飞警徽或撕警徽；若无法行动则自动撕毁。 | 回到触发前的结算路径；必要时继续处理猎人开枪、遗言、白天入口或下一夜。 |
| `sheriff_speech_order` | 夜晚结算后仍未结束，地图启用警长且当前警长存活。 | 对警长下发 `sheriff_speech_order`，目标为首发言玩家，动作表示顺时针或逆时针。 | 警长选择发言起点和方向。 | `day_discussion`。 |
| `day_discussion` | 夜晚结算后仍未结束；无存活警长时直接进入，有存活警长时等待警长决定发言顺序后进入。 | 对存活玩家依次下发 `speak`。 | 所有有资格玩家发言完成。 | `vote`。 |
| `vote` | 白天发言完成。 | 对存活玩家依次下发 `vote`。 | 所有有资格玩家投票完成。 | 放逐结算，进入 `sheriff_badge_action`、`hunter_action`、`last_words`、下一夜或 `game_over`。 |
| `hunter_action` | 猎人死亡且可开枪。 | 对猎人下发 `hunter_shoot`。 | 开枪或跳过被接受。 | 回到触发前的结算路径；若猎人带走当前警长，先进入 `sheriff_badge_action`。 |
| `last_words` | 有出局玩家可发表遗言。 | 对待遗言玩家依次下发 `last_words`。 | 待遗言队列清空。 | 回到触发前的结算路径。 |
| `game_over` | 胜负产生。 | 无玩家行动。 | 记录胜负结果并冻结本局玩法输入。 | `replay_round`。 |
| `replay_round` | 本局胜负结果已经冻结。 | 由狼人杀房间模块生成复盘回合数据并下发。 | 复盘回合数据生成完成。 | `post_game_summary`。 |
| `post_game_summary` | 复盘回合数据生成完成。 | 对玩家下发 `post_game_summary`。 | 赛后总结收集完成。 | `mvp_vote`。 |
| `mvp_vote` | 赛后总结完成。 | 对玩家下发 `mvp_vote`。 | MVP 投票完成。 | `completed`。 |
| `completed` | MVP 投票完成。 | 无。 | 等待房间结束。 | 无。 |

## 自动跳过

- 缺少对应身份、行动者已死亡、能力已经耗尽或当前目标集合为空时，狼人杀房间模块可以自动推进。
- 自动跳过仍应产生可调试的阶段事件，但不能伪造玩家输入。
- 自动跳过不能绕过胜负检查；每个可能产生死亡或放逐的阶段结束后都要检查胜负。
- `sheriff_speech_order` 仅在有存活警长时生成；没有存活警长或警长无法行动时，白天按座位顺序发言。
- `sheriff_badge_action` 仅在当前警长死亡且胜负未产生时生成；死亡警长无法处理时自动撕毁警徽。

## 主机推进闸门

阶段状态机只描述规则顺序；实际运行由房主端串行推进。每次推进前必须同时满足：

- 游戏未处于 `paused`。
- 中心展示没有未完成的 presentation ACK。
- 设备任务通道没有待返回的真人或远程机器人任务。
- 没有等待中的 AI 模型请求。

中心展示 gate 的确认粒度是设备，不是玩家。真人玩家、观战设备都需要对自己可见的广播 ACK；AI 机器人玩家没有独立设备，不参与 ACK。开启语音时，设备在语音播放完成后确认；未开启语音时，设备按文本内容等待，最低 5 秒后确认。

真人玩家的发言和行动通过设备任务通道完成：主机创建任务，路由到该玩家所在设备，设备提交结果，主机再转换为规则模块输入。AI 机器人玩家最终也必须回到同一条统一行动结果入口，不能直接改写阶段或历史。

## 暂停与恢复

- 真人玩家设备断线且不是主动离开时，游戏进入暂停，保留席位并显示暂停原因。
- 暂停会清理展示 ACK、设备任务、机器人请求跟踪和自动推进等待态，避免旧回调在重连后错误推进。
- 暂停期间收到的旧设备任务结果应被忽略。
- 真人玩家重连后，如果没有其它离线真人，清除暂停并重新调度自动推进。
- 全部真人玩家主动退出后，房间模块销毁当前房间，不继续等待 AI 机器人。

## 主要流程

### 开局

```text
房间模块确认人数和 ready
  -> start_game()
  -> 根据 map_id 和 player_count 选择内部编排
  -> 读取地图规则配置并生成身份配置
  -> 洗牌并发身份
  -> 初始化夜晚或警长竞选阶段
  -> 返回玩法状态、玩家列表、历史和行动请求
```

### 夜晚

```text
当前阶段需要夜晚行动
  -> build_action_request()
  -> 主持人消息进入中心展示并等待可见设备 ACK
  -> 狼人杀真人玩家模块或狼人杀 AI 玩家模块收集玩家结果
  -> 真人通过 device_task 返回，AI 通过模型输出解析返回
  -> submit_action_result()
  -> 记录狼人、预言家、女巫、守卫等行动
  -> 返回 public_events / private_events / effect_requests
  -> 所需行动完成后结算死亡和公开信息
  -> 如果死亡玩家包含警长且胜负未产生，先处理飞警徽或撕警徽
  -> 进入白天
```

### 白天

```text
公布夜晚结果
  -> 中心展示并等待可见设备 ACK
  -> 如死亡玩家包含警长，先由死亡警长飞警徽或撕警徽
  -> 如有猎人开枪或遗言，继续完成对应流程
  -> 有存活警长时生成警长发言顺序请求
  -> 警长指定首发言位和顺时针/逆时针方向
  -> 生成发言请求
  -> 收集玩家发言
  -> 中心展示本次发言并等待可见设备 ACK
  -> 生成投票请求
  -> 收集投票
  -> 放逐；若放逐当前警长，先处理飞警徽或撕警徽
  -> 猎人开枪和遗言
  -> 胜负检查
  -> 下一夜或 game_over
```

### 赛后

```text
game_over
  -> replay_round：生成复盘回合数据并按地图规则包下发
  -> post_game_summary：生成玩家赛后总结请求
  -> 收集总结和 MVP 投票
  -> completed
  -> debug 打印每个身份 / 观察者视角的历史对话文本数组
  -> 写入 AI 机器人长期记忆和本局记忆压缩数据
  -> 下一局开局前清空上一局 history、中心展示、狼队私聊、prompt 日志和会话记忆
```

复盘是狼人杀房间模块对本局玩法的赛后回合，不是页面。页面、场景或 UI 只渲染 `replay_round` 下发的数据，不能自行拼接夜晚行动、身份、投票和死亡路径。
