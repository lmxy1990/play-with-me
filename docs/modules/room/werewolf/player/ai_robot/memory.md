# 狼人杀 AI 机器人玩家记忆更新

更新时间：2026-05-16

记忆更新只发生在狼人杀房间模块接受行动结果之后。`memory_update` 是通用分层更新载荷，不是自然语言摘要，也不是模型推理全文。

## 触发条件

只有满足以下条件才能构建 `memory_update`：

- `WerewolfRuleUpdateResult.ok = true`。
- 行动、发言或结果已经被狼人杀房间模块接受。
- 更新材料属于当前机器人输入范围。
- 更新材料不包含模型草稿、未确认 UI 输入或被拒绝的行动。

## 输入材料

| 材料 | 是否可进入 | 说明 |
| --- | --- | --- |
| 已接受公开发言 | 可以 | 进入当前机器人对话材料。 |
| 已接受狼队交流 | 仅狼人范围 | 只进入对应狼人机器人视角。 |
| 已公开投票结果 | 可以 | 进入公开事件材料。 |
| 当前机器人自己的行动 | 可以 | 进入行动经验材料。 |
| 当前机器人输入范围外的夜晚行动 | 不可以 | 不进入任何当前机器人记忆更新。 |
| 复盘回合数据 | 仅复盘回合允许后 | 游戏结束后由复盘回合显式提供。 |
| 模型推理过程 | 不可以 | 不写入记忆。 |
| 模型草稿 | 不可以 | 未被规则接受。 |

## 记忆引用方式

记忆材料可以保留本局席位人物摘要，用于让机器人理解“几号位是谁”和延续发言关系。

固定引用方式：

- 使用 `seat_number` 表示方向，也就是发言中的“X 号”。
- 可以附带当前玩家名字，例如“5号（阿明）”。
- 关系记忆、事件记忆和复盘候选都按席位编号引用本局对象。
- 跨局长期记忆只能沉淀可泛化的行为风格或策略经验。

## 分层建议

`memory_update` 可以按下列层次组织：

| 层 | 狼人杀材料 |
| --- | --- |
| `working` | 当前局内短期目标、当前阶段判断、待观察对象。 |
| `episodic` | 已确认的关键事件、发言、投票、行动结果。 |
| `relationship` | 对其它玩家风格、可信度、互动结果的已确认观察。 |
| `semantic` | 机器人学到的通用地图规则、行动经验和策略约束。 |
| `reflection` | 游戏结束后允许沉淀的复盘判断。 |

记忆模块决定最终写入、合并、降权、拒绝、衰减、忽略或延后维护。

## 会话结束更新

游戏结束后，本模块可以基于复盘回合下发数据构建 `session_end_memory_update`：

- 本局地图、人数和席位。
- 机器人最终身份和阵营。
- 关键公开发言和投票。
- 当前机器人输入范围内或复盘回合允许的夜晚行动。
- 胜负结果。
- 机器人自己的关键决策。
- 复盘回合允许公开后的关系和策略反思。

会话结束更新必须等待复盘回合允许后生成。

## 禁止规则

- 当前机器人输入范围外的信息不得进入 `memory_update`。
- 狼人杀房间模块拒绝的行动不得进入 `memory_update`。
- 模型草稿不得进入 `memory_update`。
- 推理过程不得直接写入记忆。
- TTS 播放结果不得改变记忆更新材料。
