# 象棋 AI 玩家模块

更新时间：2026-05-23

象棋 AI 玩家模块是具体游戏 AI 玩家实现，负责把象棋房间模块发出的行棋请求和真人发言触发的聊天请求转换成 AI 可处理的输入，再把模型输出解析成统一象棋行动结果或聊天文本。

## 模块定位

```text
玩家模块
  -> AI 玩家模块
       -> 象棋 AI 玩家模块
            -> 象棋局面上下文
            -> 行棋 prompt / schema
            -> 聊天 prompt / schema
            -> 模型输出解析
            -> XiangqiPlayerActionResult
```

象棋 AI 玩家模块只负责“AI 如何产生一次象棋响应”。棋局状态、走法合法性、胜负和复盘仍由象棋房间模块负责。

## 能力边界

象棋 AI 玩家模块负责：

- 按 AI 座位构建公开象棋局面上下文。
- 行棋时读取棋盘、棋谱、当前行棋方、合法走法候选和规则摘要。
- 聊天时读取最近真人发言、公开聊天记录和当前局面摘要。
- 从机器人档案读取模型配置引用和声音配置引用。
- 在控制设备本机读取完整模型配置并调用模型管理模块。
- 渲染行棋和聊天各自的 prompt、user payload 和 response schema。
- 解析模型输出为结构化走法或聊天文本。
- 把结果包装成统一 `XiangqiPlayerActionResult` 或已确认聊天候选。

象棋 AI 玩家模块不负责：

- 通用机器人档案、模型配置和长期记忆存储。
- 房间网络、主机选举、重连认证和快照同步。
- 象棋权威局面、走法最终校验、胜负判定。
- 真人 UI 交互。

## AI 行棋

AI 行棋输入应包含：

- 当前 AI 是红方还是黑方。
- 当前棋盘结构化状态。
- 当前行棋方。
- 最近若干步棋谱。
- 当前可选合法走法数组。
- 是否被将军。
- 当前规则配置，包括悔棋、求和、认输、`clock_enabled`，以及计时开启时的 `time_limit_ms` 和棋钟状态。

AI 行棋输出只允许：

```json
{
  "action": "move",
  "from": {"file": 0, "rank": 0},
  "to": {"file": 0, "rank": 1}
}
```

也可以输出认输、求和、同意/拒绝求和、申请悔棋、同意/拒绝悔棋等结构化行动。模型不能输出棋盘补丁，不能声称已经改变局面。

求和和悔棋响应：

- AI 收到求和请求时，必须输出 `draw_accept` 或 `draw_decline`。
- AI 收到悔棋请求时，必须输出 `undo_accept` 或 `undo_decline`。
- 响应请求不允许夹带走棋。
- 模型输出解析失败时返回结构化错误，不默认同意。

## AI 聊天

AI 聊天触发条件：

- 只有真人玩家公开发言被房间接受后才触发。
- AI 不主动开局发言，不因自己走棋后自动发言。
- 聊天回应不改变棋盘、不消耗走棋请求、不切换行棋方。

AI 聊天输入应包含：

- 真人最新发言。
- 最近公开聊天。
- 当前棋局摘要。
- AI 自己的座位、阵营和机器人性格摘要。

AI 聊天输出只允许文本和可选情绪/语气元数据，不允许夹带走棋结果。

## 记忆

第一版建议不写机器人长期记忆，直到通用记忆模块稳定后再打开。需要写入时，只能在象棋房间模块接受结果后生成通用 `memory_update`：

- 已接受的关键棋局结果。
- 已公开的聊天内容。
- 对局结果和对手风格摘要。

模型草稿、非法走法、被拒绝聊天和未公开输入不得写入记忆。

## 代码归属

目标目录：

```text
scripts/player/xiangqi/ai/
  xiangqi_ai_player_factory.gd
  ai_xiangqi_player_runtime.gd
  ai_xiangqi_turn_context_builder.gd
  ai_xiangqi_output_parser.gd
  ai_xiangqi_prompt_renderer.gd
  ai_xiangqi_response_schema_builder.gd
  ai_xiangqi_chat_flow.gd
```

当前第一版已实现象棋 AI 玩家工厂、行棋上下文构建、结构化输出解析和本地运行时。AI 到自己回合时先基于合法走法列表生成结构化 `move`，再提交给象棋房间模块校验和落盘。模型 prompt、response schema 和聊天触发流仍按上述目录继续补齐，不应写入房间公开快照。

## 维护规则

- 行棋 prompt 和聊天 prompt 必须分离。
- AI 行棋结果必须回到象棋房间模块校验。
- AI 聊天不得推进棋局。
- prompt、schema、模型配置和 API Key 不进入房间快照或公开历史。
